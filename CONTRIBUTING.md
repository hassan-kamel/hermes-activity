# Contributing to Hermes Activity

Bug reports, documentation improvements, regression tests and focused pull requests are welcome. Please check existing issues and discuss substantial features before building them.

## Report a bug

Include the Activity version, Hermes version, Node version, operating system, selected profile type (local or remote), reproduction steps, expected behavior and actual behavior. State whether the problem occurs during a passive cached read or an explicit refresh. A minimal redacted response shape is useful for provider parsing issues.

Never post API keys, bearer tokens, cookies, auth files, profile environment files, raw databases or private session content. Do not attach full environment dumps or unreviewed stdout/stderr. Remove account identifiers and sensitive usage details from screenshots and response fixtures. If a credential was exposed, revoke it first.

Report security vulnerabilities privately through [GitHub private vulnerability reporting](https://github.com/hassan-kamel/hermes-activity/security/advisories/new) when available. If unavailable, ask the maintainer for a private channel without publishing exploit details or credentials.

## Set up development

Prerequisites: Hermes Agent >=0.21.7 with `hermes` on PATH, Node >=22.18, npm and Python 3 available as `python3` for the backend regression tests. Hermes supplies the production Python environment. Provider accounts and credentials are not required for the fixture-based test suite.

```sh
git clone https://github.com/hassan-kamel/hermes-activity.git
cd hermes-activity
npm ci
npm test
npm run typecheck
npm run build
hermes plugins validate .
```

Create a focused branch in your fork. Use a dedicated disposable `HERMES_HOME` profile for manual testing, not your primary profile. `npm run install:local` builds and copies the desktop bundle into that home's `desktop-plugins/hermes-activity/` directory. The Activity desktop surface must be enabled in Hermes Desktop. Do not commit profile data or caches.

## Code map

- `src/`: React desktop surface, payload parsing and presentation.
- `commands.py`, `activity_data.py`: Hermes plugin commands and read-only local activity aggregation.
- `scripts/provider-history.ts`: explicit provider requests, normalized history and cache handling.
- `scripts/provider-usage.ts`: provider response normalization.
- `tests/`: Node test runner coverage, including isolated Python/backend and real-CLI checks.
- `plugin.yaml`: capabilities, runtime requirements and declared credential routes.
- `desktop/plugin.js`: committed distributable, generated by `npm run build`.

## Required invariants

- Passive reads stay cache-only: no network calls, secret resolution, credential broker requests or stdin reads.
- Explicit refresh uses public Hermes credential routes only. Never discover credentials from private files, CLI stores, JWT parsing or inherited arbitrary environment variables. Keep the child environment narrowly allowlisted.
- Never put credential values in logs, error messages, caches, desktop payloads, fixtures or public reports. Provider errors must not echo raw HTTP bodies or subprocess stderr.
- Preserve unknown metrics as null, not zero. Only genuine dated provider buckets may enter daily history. Do not derive daily usage from undated totals, quotas, percentages or plan limits.
- Disclose account/workspace scope and partial coverage. Provider-wide data is not necessarily Hermes-only.
- Keep refresh bounded, caches profile-local and private, and raw responses out of caches. Preserve legacy normalized-cache compatibility.
- Ship a self-contained desktop ESM bundle. Runtime imports are limited to `@hermes/plugin-sdk`, `react` and `react/jsx-runtime`.
- Preserve license notices, including Quota's MIT attribution in `THIRD_PARTY_NOTICES.md`.

## Tests and pull requests

Add a failing regression test before fixing a bug. Use sanitized synthetic fixtures and injected network/broker responses. Cover missing and malformed metrics, authentication failures and cache-only reads where relevant. If changing a provider adapter, test its normalized output and an end-to-end refresh/cache path. A fixture test is not evidence of a live provider request or native Windows execution.

Before submitting:

```sh
npm test
npm run typecheck
npm run build
hermes plugins validate .
npm audit --omit=dev
git diff --check
```

Include the regenerated `desktop/plugin.js` when the UI changes. Describe the problem, linked issues, chosen fix, privacy impact, actual checks run and any platform/live-test limitations. Keep unrelated refactors out of a bug fix. Screenshots are useful for UI changes, but do not replace keyboard, accessibility or runtime testing. Maintainers handle version bumps, release tags and catalog publication.
